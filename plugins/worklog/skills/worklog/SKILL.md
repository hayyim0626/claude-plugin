# worklog — 개인 작업 기록

목적은 보고가 아니라 **기억의 외부화**다. 반년 뒤의 내가 코드를 다시 열지 않고도 그때 무엇을 왜 했는지 알아야 하고, 그 기록으로 포트폴리오·이력서를 쓴다. 그래서 한 일 옆에 반드시 **판단**을 남기고, 읽는 사람이 "엔지니어인 미래의 나"라는 전제로 쓴다.

## 위치와 설정

- 기록 저장소: `$WORKLOG_DIR` (기본 `~/worklog`). 설정은 `$WORKLOG_DIR/config.json` — `repos[]`(경로·프로젝트명·저장소별 `doc_dirs`), `doc_dirs`, `sessions`, `allowed_emails`.
- 스크립트: `${CLAUDE_PLUGIN_ROOT}/scripts/collect.sh SINCE UNTIL [--status] [--no-sessions]`, `${CLAUDE_PLUGIN_ROOT}/scripts/redact-check.sh [files]`.
- 상태: `$WORKLOG_DIR/.state/last_checked` — catchup 이 마지막으로 검사한 날짜(YYYY-MM-DD).
- 파일 규칙은 `$WORKLOG_DIR/README.md` 가 정답이다. 처음 실행이면 먼저 읽는다.

## 인자

`$ARGUMENTS` 의 첫 단어가 모드다. 없으면 `daily`.
`--headless` 가 있으면 **질문 없이 파일만 쓰고 끝낸다**(커밋은 run.sh 몫). 없으면 초안을 보여 주고 확인 뒤 커밋·푸시한다.

## 공통 규칙

### 공개 경계 (README "공개 경계")

- 쓰지 않는다: 소스코드·코드 블록·설정값·URL·키·토큰·고객 개인정보·`allowed_emails` 외 이메일.
- 쓴다: 기관명·회사명·프로젝트명·제품명·기술 스택·결정과 근거. 파일 경로는 디렉토리 수준까지(`apps/portal-be`).
- 저장 전 `redact-check.sh` 를 돌리고, 걸리면 그 줄을 고친 뒤 다시 돌린다.

### 프로젝트와 영역

- 프로젝트 이름은 `config.repos[].project` 를 그대로 쓴다. 세션의 디렉토리와 대화 내용이 가리키는 프로젝트가 다르면 **내용**을 따른다.
- 같은 커밋(제목·날짜 동일, 해시만 다름)이 두 저장소에 보이면 하나로 센다.
- 항목 제목 뒤에 **영역을 대괄호로** 붙인다. 어휘는 고정: `프론트` `백엔드` `온체인` `인프라` `데이터` `리서치` `제품 결정` `외부 협업` `AI 활용` `도구`. 여러 개면 ` · ` 로 잇는다. 예: `[백엔드 · 온체인]`. 이 어휘 밖의 단어를 만들지 않는다(grep 으로 페르소나별 추출에 쓴다).

### 문체 — 가장 중요

읽는 사람은 **코드를 잊은 엔지니어**다. 그 사람이 이해할 수 있게 쓴다.

1. **항목 = 제목 한 줄 + 설명 문단.** daily 는 2~3문장, weekly 는 1문장, monthly 는 프로젝트별 2~5문장. 설명 순서는 "왜 문제였나 → 무엇을 바꿨나 → 그래서 무엇이 되나". 한 줄에 괄호·가운뎃점으로 키워드를 나열하지 않는다.
2. **업계 용어·제품명·기술명은 그대로 쓴다.** 스켈레톤 UI, Codex, 아카이브 DB, ERC-4337, RS512, SFTP, Fireblocks, BC 서버처럼 엔지니어가 아는 이름은 풀어 쓰지 않는다. 풀어 쓸 것은 **우리 코드 안의 이름**뿐이다 — 변수·컬럼·함수·플래그·env 이름(`ref`, `lock`, `pending`, `wb-withdraw`)은 "재고 잠금 식별자", "진행 상태 컬럼"처럼 역할로 쓴다.
3. **사실을 구체적으로, 비유 없이.** "우리끼리 돌던 결제가 남과 맞춰야 하는 결제로" 같은 표현 대신 "내부 검증만 하던 결제를 실제 BC 서버와 통신해 검증하기 시작했다"로 쓴다. 감상·평가("잘 됐다", "의미 있는")도 쓰지 않는다.
4. **판단은 "무엇을 어떻게 하기로 했고, 안 그러면 무슨 일이 생기나."** 이유를 모르면 이유 없이 쓴다. 지어내지 않는다. 설계·제품·운영·외부 협업 판단만 남기고 작업 습관(커밋 분리, 문서 정리 순서)은 뺀다. daily 는 하루 5~8줄.
5. 한국어. 문장은 마침표로 끝낸다(제목 줄은 마침표 없음). `*` 금지. 커밋 해시 없음. 수는 근거 절에만. AI 모델·도구는 이름으로(Claude, Codex, Claude in Chrome, 아티팩트).

### 판단 추출

세 출처에서 뽑는다. 우선순위 순.

1. **ADR** — collect 의 `=== DOCS ===` 에 `docs/adr/*.md` 가 A 또는 M 으로 있으면 **그 저장소에서 파일을 직접 읽는다**(`Read {repo}/{path}`). "결정" 절과 버전 이력 마지막 행에서 그날 추가된 결정을 요약한다. "검토한 대안" 절이 있으면 기각 이유를 챙긴다. ADR 이 없는 저장소는 PRD·report·plan 문서가 그 역할이다 — "결정"·"고려 사항"·"Open Question"·"대안" 절을 읽는다. 문서가 많으면 그 기간에 **추가(A)된 것** 위주로 읽고 수정(M)은 제목만 본다.
2. **세션 사용자 메시지** — `##### SESSIONS` 에서 방향을 정하거나 기각한 문장만 고른다: "~로 하자", "~는 빼자", "~말고 ~", "우선 ~부터", "왜 ~?" 뒤에 이어진 선택, 순서·범위·배포 결정. UI 잔손질은 원칙이 드러날 때만(예: "이메일은 굳이 안 넣어도" → 노출 정보 최소화).
3. **커밋 메시지의 " — " 뒤** — 이유가 붙은 커밋은 그 이유가 판단이다.

### AI 활용 추출

세션에서 **작업 방식**이 드러난 것만 적는다 — 아티팩트로 UI 시안을 돌린 것, Claude in Chrome 으로 외부 서비스 설정, 딥리서치 워크플로, 서브에이전트 검증, Codex 와 교차 검토, 스킬·플러그인 제작. 그날 특별한 게 없으면 절을 생략한다.

## 날짜 계산

```bash
TODAY=$(date +%F); YESTERDAY=$(date -v-1d +%F)
python3 -c "import datetime as d; x=d.date.fromisoformat('$D'); y,w,_=x.isocalendar(); print(f'{y}-W{w:02d}')"        # ISO 주
python3 -c "import datetime as d; x=d.date.fromisoformat('$D'); m=x-d.timedelta(days=x.weekday()); print(m, m+d.timedelta(days=6))"  # 월·일
```

요일 표기: `(월)` … `(일)`.

## 모드

### daily [YYYY-MM-DD] (기본 어제)

1. `collect.sh D D --status` 실행(`--status` 는 D 가 오늘일 때만 의미 있다).
2. 커밋·문서·세션이 전부 비어 있으면 **파일을 만들지 않고** "활동 없음"만 알린다.
3. ADR·PRD 변경이 있으면 판단 추출 규칙 1 대로 파일을 읽는다.
4. `daily/YYYY/MM/YYYY-MM-DD.md` 를 아래 형식으로 쓴다. 한 일은 커밋 하나하나가 아니라 **기능·주제 단위**로 묶는다(PRD·report 제목이 출발점). 잔손질 fix 는 상위 작업에 흡수. 하루 3~7항목.
5. `projects` 모드를 같은 날짜 범위로 이어서 수행한다(ADR·PRD 추가가 있을 때만).

```markdown
# 2026-09-08 (화)

## 한 일

### PADO

- XRPL 정산의 이중 발행·유령 체결 구멍 막기 [백엔드 · 온체인]
  주식은 보유 수량 일부만 게시할 수 있어서, 채권처럼 종목 단위로 재고를 잠그면 같은 주식을 두 번 게시해 증표를 중복 발행할 수 있었다. 재고 잠금을 수량 단위로 바꾸고, 잠금은 게시물이 만료될 때가 아니라 딜이 끝날 때 풀리게 했다.
  매수 트랜잭션은 서명 직후 해시를 먼저 저장하고, 결과를 모르는 상태에서는 다시 서명하지 않고 원장부터 확인한다. 체결됐는데 장애로 기록을 잃고 다시 발행하는 사고를 막기 위해서다.
  검증 항목은 Codex 가 쓴 검토안을 Claude 와 교차 검토해 작업 큐 같은 큰 구조는 빼고 실제 구멍만 남겼다.

- 페이지별 스켈레톤 UI 적용 [프론트]
  모든 페이지가 같은 스켈레톤을 쓰던 것을 표·상세·대시보드 세 레이아웃에 맞는 스켈레톤으로 나눴다. 라이트 모드에서 스켈레톤이 카드 배경과 같은 흰색이라 안 보이던 문제도 고쳤다.

### Wallet

- EIP-8141 조사 [리서치 · 온체인]
  다음 이더리움 업그레이드에 포함될 예정인 제안으로, ETH 대신 스테이블코인으로 가스비를 낼 수 있게 된다. 지갑 프로젝트에 어떤 의미인지 정리했다.

## 판단

- 재고 잠금은 게시물이 아니라 딜에 묶는다. 견적 요청의 유효시간이 딜보다 짧아 딜 진행 중 게시물이 만료되는 게 정상인데, 그때 잠금이 풀리면 같은 실물을 다시 게시해 증표가 두 번 발행된다. IOU 는 발행 상한이 없어 재고 잠금이 유일한 방어선이다. (ADR-0011 v1.1)
- 기관이 정산 완료를 보고하는 API 는 Canton 딜만 받는다. XRPL 은 원장 확인 없이 API 키만으로 정산 완료를 찍을 수 있는 구멍이었다.

## AI 활용

- Codex 가 쓴 정산 검증안을 Claude 에 넘겨 교차 검토하고, 두 모델의 답을 서로 되먹여 여러 번 고친 뒤 구현에 들어갔다.

## 근거

- PADO 커밋 3개 (portal-be, portal-fe, mock 재고 API, 문서). ADR-0044 신규, ADR-0011 v1.1, ADR-0021 v1.4. PRD·report 3건, 리서치 2건
- 세션: PADO 4건, Wallet 1건
```

### weekly [YYYY-MM-DD | this] (기본 지난주)

기간: 인자 없음 → 직전 월~일. 날짜 → 그 날짜가 속한 월~일. `this` → 이번 주 월~오늘.

1. 그 주의 `daily/` 파일을 모두 읽는다(Glob). 이것이 1차 재료다.
2. `collect.sh 월 일 --no-sessions` 로 daily 가 놓친 커밋·문서를 보정한다. daily 가 하나도 없으면 세션까지 포함해 수집하고, 판단 하이라이트는 판단 추출 규칙(문서·커밋 이유)으로 직접 뽑는다. 커밋·문서·세션이 전부 비어 있으면 파일을 만들지 않는다.
3. 작업 단위로 묶는다 — **3~7개**. 회의·잔손질·다른 사람 커밋은 뺀다. 코드 없어도 결정·검증·문의는 넣는다. 8개가 넘으면 상위 주제로 다시 묶는다. 프로젝트가 둘 이상이면 프로젝트 소제목으로 나눈다.
4. 제목 바로 아래에 **한 줄 요약**을 인용문으로 둔다 — 종이 캘린더에 그대로 옮겨 적는 줄이다. 항목마다 `{무엇}({핵심 수단·범위})` 꼴 명사구, 쉼표+공백으로 잇고 마침표 없음, 프로젝트명은 구분이 필요할 때만 앞에. 예: `PADO XRPL 병행 레그 구축(PermissionedDEX), 토스증권 국내주식 실시간 가격 API 연동, RFQ 화면·거래 벤치마크 아티팩트 작성, VASP 규제 대응을 위한 Turnkey 기술검증`
5. `weekly/YYYY/YYYY-Www.md`:

```markdown
# 2026-W23 · 06-01(월) ~ 06-07(일)

> BC Pay 회원 탈퇴 구현(아카이브 DB·온체인 allowance 회수), 결제 속도 병목 진단과 Base 네이티브 AA 전환(Fireblocks 실측·CDP Smart Account), 잔고·한도 초과 결제 사전 거절 통일, 결제·온보딩 화면 개편, 어드민 결제 타임라인 보강, 디자인 시스템 컴포넌트 라이브러리 구축

### BC Pay
- 회원 탈퇴 구현 [프론트 · 백엔드 · 온체인 · 제품 결정]
  미정산 건이 없는지 확인한 뒤 계정 데이터를 아카이브 DB 로 이관해 재접근을 막고, 회사가 고객 지갑에서 인출할 수 있던 온체인 allowance 도 회수한다.
- 결제 속도 병목 진단과 Base 네이티브 계정 추상화 전환 [백엔드 · 온체인 · 리서치]
  결제 6.5초 중 5초가 Fireblocks 내부 서명 대기임을 실측으로 밝히고, CDP Smart Account 로 결제 경로를 바꾸는 시험을 테스트넷에서 마쳤다.

### Design System
- 컴포넌트 라이브러리 구축 [프론트 · 도구]
  Figma 를 유일한 원본으로 두고 shadow 토큰과 컴포넌트 카탈로그를 만들었다.

## 판단 하이라이트

- 결제 경로에서 Fireblocks 를 뺀다. 결제 시간의 대부분이 Fireblocks 내부 대기였고, 브로드캐스트만 직접 하는 안은 절감 폭이 작았다.
- 탈퇴할 때 온체인 allowance 를 0 으로 되돌린다. 서버에서 계정만 지우면 고객 지갑에 대한 인출 권한이 온체인에 영구히 남는다.

## 근거

- 회원 탈퇴 — BC Pay 커밋 5개, PRD 2건, 회원 생애주기 정책 문서
- 결제 속도 — 커밋 3개, PRD 4건
- 저장소 활동 없음: PADO, Canton, Wallet, Partner API, Tooling
```

판단 하이라이트는 그 주의 판단 중 **이력서에 남을 만한 것 3개 이내**.

### monthly [YYYY-MM] (기본 지난달)

git 을 다시 훑지 않는다. 그 달의 `weekly/` 파일과 `projects/*.md` 에서 그 달 날짜의 항목을 읽어 `monthly/YYYY/YYYY-MM.md` 를 쓴다.

```markdown
# 2026-06

## BC Pay

내부 검증만 하던 결제를 실제 BC 서버와 통신해 검증하기 시작한 달이다. 월초에는 결제가 6.5초 걸리는 원인을 실측해 Fireblocks 내부 대기임을 밝히고, Base 네이티브 계정 추상화로 결제 경로를 바꿨다. 가맹점에는 온체인 확정을 기다리지 않고 먼저 응답을 돌려주고 확정 확인은 백그라운드로 옮겨 시간을 더 줄였다.

월 중반부터 인수사 실거래 데이터가 들어왔는데 첫 매칭이 한 건도 되지 않았다. QR 원문을 대조하던 방식을 참조번호 매핑으로 바꾸고, 환불도 QR 없이 원거래 식별자만으로 처리하게 했다. 월말에는 SFTP 로 받는 일별 정산 파일을 파싱해 대사하는 파이프라인과 어드민 화면을 만들었다.

## Partner API

파트너 인증 JWT 의 서명을 대칭키에서 RS512 비대칭키로 바꿨다. 대칭키로는 파트너 secret 이 게이트웨이 DB 에 평문으로 남기 때문이다. API 문서는 Scalar 로 옮기고, 게이트웨이가 파트너 식별자를 헤더로 주입해 뒷단 DOS 가 요청 주체를 알 수 있게 했다.

## 이 달의 결정

- 결제 경로에서 Fireblocks 를 빼고 Base 네이티브 계정 추상화로 (BC Pay, W23)
- 결제 매칭은 QR 원문 대조가 아니라 참조번호로, 환불은 QR 없이 (BC Pay, W26)
- 파트너 인증 JWT 서명은 RS512 비대칭키로 (Partner API, W25)
```

### catchup [--headless]

맥북이 꺼져 있던 기간을 메운다. 순서:

1. `LAST=$(cat $WORKLOG_DIR/.state/last_checked)` — 없으면 어제 하루만. `START=LAST+1`, `END=어제`. `START` 가 `END-13` 보다 이르면 `END-13` 으로 자른다(최대 14일).
2. `START..END` 각 날짜에 대해 `daily/…/날짜.md` 가 없으면 **daily** 를 수행한다(활동 없는 날은 파일 없이 넘어간다). 이미 있으면 건너뛴다.
3. `START` 가 속한 주부터 `END` 까지, **일요일이 END 이하인 주**마다 `weekly/…/YYYY-Www.md` 가 없으면 **weekly**.
4. 같은 방식으로 **말일이 END 이하인 달**마다 `monthly/…` 가 없으면 **monthly**.
5. `.state/last_checked` 에 `END` 를 쓴다.
6. 마지막에 만든 파일 목록을 한 줄씩 출력한다. 채울 게 없었으면 "채울 것 없음 (last_checked=…)".

`--headless` 에서는 AskUserQuestion 을 절대 쓰지 않는다. 커밋도 하지 않는다.

## 마무리 (대화형일 때)

1. 만든/고친 파일의 내용을 보여 준다.
2. AskUserQuestion — "이대로 저장할까요?" `저장` / `수정 필요`.
3. 저장이면 `redact-check.sh {files}` → 통과 시 `cd $WORKLOG_DIR && git add -A && git commit -m "worklog: {모드} {기간}" && git push`.
4. `.state/last_checked` 는 catchup 만 갱신한다(daily 를 직접 돌린 날짜가 `last_checked` 보다 뒤면 그 날짜로 올린다).
